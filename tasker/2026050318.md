# Task 2026050318

## Goal

Upgrade this Go module to Go 1.26.2, refresh Go package dependencies from the
network, run `go fix`, analyze the code using Go package design principles,
identify three worthwhile issues, fix the highest-priority issue, and validate
the result with evidence.

## Scope

In scope:

- `go.mod`
- `go.sum`
- `worker.go`
- `master.go`
- `task.go`
- Existing Go tests
- New Go tests, if needed to prove the implementation
- Workflow artifacts under `share/2026050318/`

Out of scope:

- Changing the workflow schema or any `AGENTS.md`
- Rewriting the package around Clean Architecture, DDD, or a heavy abstraction
  style
- Removing or weakening existing tests except when a production code change
  requires a test update; any such test update must be recorded with the reason

## Constraints

- Set the Go version to `1.26.2`.
- Go packages must be resolved from the network for latest available versions;
  do not rely on or intentionally pin to local cached module versions.
- If dependency resolution, Go toolchain resolution, or package upgrade hits a
  network restriction, request permission instead of silently using local-only
  fallback behavior.
- If a package domain or module path has changed, first research the fix from
  the network. If no reliable fix is found, stop and report the blocker for the
  user to resolve.
- Run `go fix`.
- Execute tests and keep command-output evidence. Do not assume tests passed.
- Design analysis must be based primarily on Go package design principles:
  small APIs, clear ownership, simple concurrency contracts, useful exported
  names/errors, and low ceremony.
- Do not use Clean Architecture, DDD, or similar non-Go-oriented design methods
  as the basis for the analysis or changes.
- Make the smallest production-code change needed to fix the highest-priority
  issue discovered by analysis.
- Existing tests may be extended by adding new tests. Existing tests must not be
  modified unless production behavior changes require it; if modified, record
  the reason in the result artifact.

## Deliverables

- Updated Go module/toolchain configuration for Go 1.26.2.
- Dependency refresh evidence showing packages were resolved from the network.
- `go fix` execution evidence.
- A Go package design analysis identifying exactly three worthwhile issues and
  their priority.
- A fix for the highest-priority issue with the reason recorded.
- Test execution evidence, including the exact command and observed output.
- Cleanup and rollback notes in the implementation result.

## Validation

- Run a dependency/toolchain command that contacts the network or is allowed to
  download modules/toolchains as needed, using latest available module versions.
- Run `go fix ./...`.
- Run `go test ./...`.
- If tests are added or existing tests are changed, run `go test ./...` after
  the test changes.
- Record exact command outcomes in `share/2026050318/reviewer/result.md`.

## Cleanup

- Remove temporary scratch files created during implementation unless they are
  intentional reusable project artifacts.
- Keep workflow artifacts under `share/2026050318/`.
- Keep Go module cache or build cache outside the repo if custom cache paths are
  needed.

## Rollback

- If validation fails or implementation must stop, preserve artifacts and record
  the changed files and failure evidence.
- A safe rollback is to revert the task-specific changes to `go.mod`, `go.sum`,
  production Go files, and newly added or modified tests after reviewing the
  recorded evidence.
