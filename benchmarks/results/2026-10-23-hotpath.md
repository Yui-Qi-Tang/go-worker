# go-worker dispatch path changes — 2026-10-23

Go 1.27.3, darwin/arm64, Apple M5 Max, GOMAXPROCS=8. Same workloads, task counts,
and five-sample runs as the [frozen protocol](../README.md), go-worker engine only.
The five source trees ran in one session in the order ref, 1a, 1b, 1c, 1d, then
reversed, so each case has ten samples. Medians are shown; the change and p-value
are relative to ref (benchstat, Mann–Whitney U, n=10).

| Step | Commit | Change |
| --- | --- | --- |
| ref | `764b1df` | Go 1.27.3 and upgraded dependencies, before dispatch changes |
| 1a | `8e8582b` | Buffered `WorkerQueue`; releasing a worker needs no goroutine |
| 1b | `4fae617` | Async futures complete on the worker goroutine |
| 1c | `b38129e` | Queue change channel replaced only when watched |
| 1d | `cc99888` | Per-task log fields skipped when Info is disabled |

## Notes

- 1a alone slows the one-worker cases (Noop +43%, SHA2564KiB +27%) while speeding
  up eight workers. With 1b, the per-task result-waiting goroutine is gone and
  the one-worker regression disappears. A separate run of 1b without 1a measured
  Noop -13% (1 worker) and -6% (8 workers) against ref, so the two changes interact.
- When no submitter or dispatcher is waiting, 1c does not replace the channel,
  so its allocation saving varies with queue occupancy (one or two per task).
- A pre-change CPU profile of Noop with one worker spent about 74% of samples in
  the runtime scheduler and about 2.5% in package code. The remaining cost is mostly
  goroutine handoffs, which these changes reduce but do not remove.
- Wait100us medians are about 11–12% higher than on 2026-10-04 for every engine,
  including the channel baseline, so that shift comes from the host timer rather
  than this package.
